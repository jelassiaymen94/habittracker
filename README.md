# 🎯 Habit Tracker

> A clean, full-stack web app to track daily habits, visualize streaks, and view a GitHub-style activity calendar.

Built with **Spring Boot**, **Thymeleaf**, **JPA**, and **H2** as my first end-to-end Java web project — focused on real architecture, real algorithms, and a polished UI.

## ✨ Features

- ➕ **Create habits** with name and optional description (server-side validated)
- ✅ **Mark a habit done for today** — idempotent (clicking twice never duplicates)
- 🔥 **Current streak** — consecutive days ending today (or yesterday)
- 🏆 **Longest streak** — all-time best run
- 🟩 **GitHub-style 90-day activity calendar** with hover tooltips
- 🗑 **Delete habits** with cascading removal of all history
- 💾 **File-based H2 database** — survives restarts, zero install required
- 🌱 **Seed data on first run** so the demo isn't empty

## 🚀 Run Locally

**Requirements:** JDK 17+

```bash
git clone https://github.com/<your-username>/habittracker.git
cd habittracker
./mvnw spring-boot:run        # Linux/macOS
mvnw.cmd spring-boot:run      # Windows
```

Then open:

- App: **http://localhost:8080**
- H2 console: **http://localhost:8080/h2-console**
    - JDBC URL: `jdbc:h2:file:./data/habits;AUTO_SERVER=TRUE`
    - User: `sa` (no password)

## 🏗 Architecture

A classic layered Spring Boot architecture — each layer has one job:

```
Browser
   ↓
Controller   ← @Controller, handles HTTP routing
   ↓
Service      ← @Service, business logic (streaks, idempotent writes)
   ↓
Repository   ← Spring Data JPA, autogenerated SQL
   ↓
H2 Database
```

### Project Structure

```
src/main/java/habittracker/
├── HabittrackerApplication.java
├── controller/
│   ├── HabitController.java     # /habits routes
│   └── HomeController.java      # / → /habits redirect
├── service/
│   └── HabitService.java        # streak logic, mark-done logic
├── repository/
│   ├── HabitRepository.java
│   └── HabitCompletionRepository.java
├── model/
│   ├── Habit.java               # @Entity
│   └── HabitCompletion.java     # @Entity
└── SeedData.java                # demo data on first start

src/main/resources/
├── application.properties       # H2 + JPA config
└── templates/habits/
    ├── list.html
    ├── form.html
    └── show.html
```

### Data Model

```
Habit  (1) ──< (many)  HabitCompletion
  id                     id
  name                   habit_id (FK)
  description            date
  created_at
```

A `Habit` has many `HabitCompletion` rows — one per day completed. Deleting a habit cascades to its completions (`CascadeType.ALL` + `orphanRemoval = true`).

## 🧠 What I Learned

- **Spring Boot fundamentals**: auto-configuration, dependency injection, bean scanning.
- **JPA & Hibernate**: `@Entity`, `@OneToMany`, `@ManyToOne`, cascading deletes, automatic schema generation.
- **Spring Data query derivation**: writing zero SQL by naming repository methods (e.g. `findByHabitAndDateBetween`).
- **Layered architecture**: separating concerns between controller, service, and repository — and *why* it matters once business logic shows up.
- **Algorithm design**: implementing current-streak and longest-streak calculations correctly, with edge cases (empty history, broken streaks, today vs. yesterday).
- **Modern Java**: `LocalDate`, the Stream API, records, method references.
- **Form handling**: `@Valid` + `BindingResult` for server-side validation, the Post-Redirect-Get pattern to prevent duplicate submits.
- **Debugging**: reading Java stack traces top-down to root-cause real bugs (e.g. mutating an immutable list returned by `Stream.toList()`).
- **Templating with Thymeleaf**: `th:each`, `th:if/unless`, `th:field`, dynamic URL building.

## 🐛 Notable Bug I Fixed

While building the streak calculator I hit:

```
java.lang.UnsupportedOperationException
  at habittracker.service.HabitService.longestStreak(HabitService.java:106)
```

Root cause: `Stream.toList()` (Java 16+) returns an **immutable** list, but I was calling `Collections.reverse(...)` on it. Fixed by iterating the descending list in reverse instead — cleaner and avoids a list copy entirely. Lesson: always check whether a JDK API returns a mutable or immutable collection.
